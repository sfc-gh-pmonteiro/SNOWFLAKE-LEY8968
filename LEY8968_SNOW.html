Modulo 1 Fundamentos de la Ley 8968 y Arquitectura Snowflake Arts. 1-5

Que es la Ley 8968?

La Ley 8968 de 7 de julio de 2011, conocida como Ley de Proteccion de la Persona frente al Tratamiento de sus Datos Personales, es la legislacion costarricense que regula la proteccion de datos personales. Establece los derechos de los titulares, las obligaciones de los responsables del tratamiento, y las sanciones administrativas. La autoridad encargada de su cumplimiento es la PRODHAB (Agencia de Proteccion de Datos de los Habitantes), adscrita al Ministerio de Justicia y Paz.

Conceptos fundamentales (Arts. 1-4)

Principios Fundamentales (Art. 5)

La Ley 8968 establece principios rectores para el tratamiento de datos personales:

#PrincipioDescripcion
1Autodeterminacion InformativaToda persona tiene derecho a saber que datos suyos se recopilan y con que fines
2Consentimiento InformadoEl tratamiento requiere consentimiento libre, expreso e informado del titular
3Calidad de los DatosLos datos deben ser actuales, veraces, exactos y adecuados al fin para el cual fueron recopilados
4Derecho de InformacionEl titular tiene derecho a conocer la existencia de ficheros con sus datos
5Seguridad de los DatosEl responsable debe adoptar medidas tecnicas y organizativas de seguridad

Bases Legales para el Tratamiento (Arts. 5-6)

Cada tabla con datos personales debe tener documentada su base legal:

#Base LegalTag Value
1Consentimiento informado del titular (Art. 5 inc. 1)CONSENTIMIENTO
2Cumplimiento de una obligacion legal (Art. 5 inc. 2)OBLIGACION_LEGAL
3Proteccion de intereses vitales del titularINTERES_VITAL
4Interes publico o ejercicio de poderes publicosINTERES_PUBLICO
5Ejecucion de una relacion contractual con el titularRELACION_CONTRACTUAL
6Interes legitimo del responsableINTERES_LEGITIMO

Modulo 5 Politicas de Enmascaramiento Dinamico Art. 5 inc. 5, Art. 10

Las masking policies protegen datos personales en tiempo de consulta. El dato original permanece intacto en la tabla, pero usuarios no autorizados ven valores enmascarados.

1 Crear Masking Policies por Tipo de Dato

Enmascaramiento de Cedula 
USE ROLE LEY8968_PRIVACY_ADMIN;

CREATE OR REPLACE MASKING POLICY LEY8968_GOVERNANCE.POLICIES.MASK_CEDULA
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY8968_OFICIAL_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY8968_PRIVACY_ADMIN') THEN val
    ELSE CONCAT(
      LEFT(val, POSITION('-' IN val)),
      '****-****'
    )
  END
  COMMENT = 'Enmascara cedula para roles no autorizados (Art. 5, seguridad de los datos)';
Enmascaramiento de Email 
CREATE OR REPLACE MASKING POLICY LEY8968_GOVERNANCE.POLICIES.MASK_EMAIL
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY8968_OFICIAL_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY8968_PRIVACY_ADMIN') THEN val
    ELSE REGEXP_REPLACE(val, '.+\\@', '*****@')
  END
  COMMENT = 'Enmascara parte local del email (Art. 5, seguridad)';
Enmascaramiento de Telefono 
CREATE OR REPLACE MASKING POLICY LEY8968_GOVERNANCE.POLICIES.MASK_PHONE
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY8968_OFICIAL_DATOS') THEN val
    ELSE CONCAT('+506 ****-', RIGHT(val, 4))
  END
  COMMENT = 'Enmascara telefono conservando ultimos 4 digitos';
Enmascaramiento Generico (String, Number, Date) 
CREATE OR REPLACE MASKING POLICY LEY8968_GOVERNANCE.POLICIES.MASK_PII_STRING
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY8968_OFICIAL_DATOS') THEN val

Modulo 7 Politicas de Proyeccion (Projection Policies) Art. 5 inc. 3, Art. 7, Art. 10

Las Projection Policies son la tercera capa de defensa de Snowflake. Mientras las masking policies transforman valores visibles y las Row Access Policies filtran filas, las projection policies impiden que una columna aparezca en el resultado final de un query — implementando el principio de calidad de los datos y minimizacion de la Ley 8968.

AspectoRow Access PolicyProjection PolicyMasking Policy
Que controlaCuales FILAS el usuario veCuales COLUMNAS aparecen en el resultadoComo los VALORES aparecen
EnforcementFiltra silenciosamenteFAIL (bloquea query) o NULLIFY (retorna NULL)Transforma el valor
Uso en WHERE/JOINN/AColumna utilizable — solo el output es bloqueadoOpera sobre valor enmascarado
Articulos Ley 8968Art. 5, inc. 3 (Calidad)Art. 5, inc. 3 (Calidad) / Art. 7 (Sensibles)Art. 5, inc. 5 (Seguridad) / Art. 10
Defensa en Profundidad — Orden de Evaluacion en Snowflake
Capa 1: Row Access Policy → filtra FILAS (quien ve cuales registros)
Capa 2: Projection Policy → bloquea COLUMNAS en el output (quien ve cuales campos)
Capa 3: Masking Policy → transforma VALORES visibles (como aparecen los datos)

En la tabla CLIENTES, las tres capas estan activas simultaneamente.

1 Crear Projection Policies

USE ROLE ACCOUNTADMIN;

  TO ROLE LEY8968_PRIVACY_ADMIN;

CREATE OR REPLACE PROJECTION POLICY LEY8968_GOVERNANCE.POLICIES.PROJ_SENSITIVE_BLOCK
  AS () RETURNS PROJECTION_CONSTRAINT ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY8968_OFICIAL_DATOS')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    WHEN IS_ROLE_IN_SESSION('LEY8968_PRIVACY_ADMIN')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    ELSE PROJECTION_CONSTRAINT(ALLOW => false)
  END
  COMMENT = 'Bloquea proyeccion de datos sensibles (Art. 7 Ley 8968)';

CREATE OR REPLACE PROJECTION POLICY LEY8968_GOVERNANCE.POLICIES.PROJ_PII_NULLIFY
  AS () RETURNS PROJECTION_CONSTRAINT ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY8968_OFICIAL_DATOS')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    WHEN IS_ROLE_IN_SESSION('LEY8968_PRIVACY_ADMIN')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    ELSE PROJECTION_CONSTRAINT(ALLOW => false, ENFORCEMENT => 'NULLIFY')
  END
  COMMENT = 'Retorna NULL para columnas PII no autorizadas (Art. 5, inc. 3 Ley 8968)';

Modulo 8 Derechos del Titular (ARCO) Arts. 8-9

Los Arts. 8-9 de la Ley 8968 garantizan al titular derechos sobre sus datos, conocidos como derechos ARCO (Acceso, Rectificacion, Cancelacion, Oposicion). Implementamos cada derecho como un stored procedure con auditoria automatica.

Derecho ARCOArticuloDescripcionProcedure
AccesoArt. 8Confirmar existencia y obtener acceso a sus datos personalesARCO_ACCESS
RectificacionArt. 9Corregir datos inexactos, incompletos o desactualizadosARCO_CORRECTION
CancelacionArt. 9Eliminar o anonimizar datos cuando ya no sean necesariosARCO_DELETE
PortabilidadArt. 8Exportar datos en formato estructuradoARCO_PORTABILITY

1 Crear Tabla de Auditoria ARCO

USE ROLE LEY8968_OFICIAL_DATOS;

CREATE OR REPLACE TABLE LEY8968_GOVERNANCE.AUDIT.ARCO_LOG (
  REQUEST_ID    STRING DEFAULT UUID_STRING(),
  REQUEST_TYPE  STRING,
  TITULAR_ID    STRING    COMMENT 'Cedula o identificador del titular',
  REQUESTED_BY  STRING DEFAULT CURRENT_USER(),
  REQUESTED_AT  TIMESTAMP_LTZ DEFAULT CURRENT_TIMESTAMP(),
  STATUS        STRING DEFAULT 'PENDIENTE',
  COMPLETED_AT  TIMESTAMP_LTZ,
  DETAILS       VARIANT
)
COMMENT = 'Log de solicitudes de derechos del titular (Arts. 8-9 Ley 8968)';

2 Derecho de Acceso (Art. 8)

CREATE OR REPLACE PROCEDURE LEY8968_GOVERNANCE.AUDIT.ARCO_ACCESS(
  TITULAR_CEDULA STRING
)
RETURNS TABLE()
LANGUAGE SQL
AS
$$
BEGIN
  INSERT INTO LEY8968_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, STATUS, COMPLETED_AT)
  VALUES
    ('ACCESO', :TITULAR_CEDULA, 'CONCLUIDO', CURRENT_TIMESTAMP());

  LET rs RESULTSET := (
    SELECT ID, NOMBRE, CEDULA, EMAIL, TELEFONO, FECHA_NACIMIENTO,
           DIRECCION, DISTRITO, CANTON, PROVINCIA, FECHA_REGISTRO
    FROM EMPRESA_DEMO_CR.DATOS_CLIENTES.CLIENTES
    WHERE CEDULA = :TITULAR_CEDULA
  );
  RETURN TABLE(rs);
END;
$$;

3 Derecho de Rectificacion (Art. 9)

CREATE OR REPLACE PROCEDURE LEY8968_GOVERNANCE.AUDIT.ARCO_CORRECTION(
  TITULAR_CEDULA STRING,
  CAMPO          STRING,
  NUEVO_VALOR    STRING
)
RETURNS STRING
LANGUAGE SQL
AS
$$
BEGIN
  INSERT INTO LEY8968_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, DETAILS)
  SELECT 'RECTIFICACION', :TITULAR_CEDULA,
     OBJECT_CONSTRUCT('campo', :CAMPO, 'nuevo_valor', :NUEVO_VALOR);

  IF (:CAMPO = 'EMAIL') THEN
    UPDATE EMPRESA_DEMO_CR.DATOS_CLIENTES.CLIENTES
    SET EMAIL = :NUEVO_VALOR WHERE CEDULA = :TITULAR_CEDULA;
  ELSEIF (:CAMPO = 'TELEFONO') THEN
    UPDATE EMPRESA_DEMO_CR.DATOS_CLIENTES.CLIENTES
    SET TELEFONO = :NUEVO_VALOR WHERE CEDULA = :TITULAR_CEDULA;
  ELSEIF (:CAMPO = 'DIRECCION') THEN
    UPDATE EMPRESA_DEMO_CR.DATOS_CLIENTES.CLIENTES
    SET DIRECCION = :NUEVO_VALOR WHERE CEDULA = :TITULAR_CEDULA;
  ELSE
    RETURN 'Error: Campo no permitido para rectificacion via ARCO.';
  END IF;

  UPDATE LEY8968_GOVERNANCE.AUDIT.ARCO_LOG
  SET STATUS = 'CONCLUIDO', COMPLETED_AT = CURRENT_TIMESTAMP()
  WHERE TITULAR_ID = :TITULAR_CEDULA
    AND REQUEST_TYPE = 'RECTIFICACION'
    AND STATUS = 'PENDIENTE';

  RETURN CONCAT('Campo ', :CAMPO, ' rectificado con exito para el titular ', :TITULAR_CEDULA);
END;
$$;

4 Derecho de Cancelacion / Anonimizacion (Art. 9)

CREATE OR REPLACE PROCEDURE LEY8968_GOVERNANCE.AUDIT.ARCO_DELETE(

    PROVINCIA        = 'XX',

USE ROLE ACCOUNTADMIN;

SELECT
  ah.USER_NAME,
  qh.ROLE_NAME,
  ah.QUERY_START_TIME,
  boa.VALUE:objectName::STRING AS OBJECT_ACCESSED,
  boa.VALUE:objectDomain::STRING AS OBJECT_TYPE,
  ah.QUERY_ID

  JOIN SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY qh

  AND boa.VALUE:objectName::STRING ILIKE '%CLIENTES%'

2 Reporte de Cobertura de Tags Ley 8968

SELECT
  t.TABLE_CATALOG AS DATABASE_NAME,
  t.TABLE_SCHEMA  AS SCHEMA_NAME,
  t.TABLE_NAME,
  t.ROW_COUNT,
  COALESCE(tr.TAG_VALUE, '*** SIN TAG ***') AS LEY8968_CATEGORY,
  CASE
    WHEN tr.TAG_VALUE IS NOT NULL THEN 'CONFORME'
    ELSE 'PENDIENTE'
  END AS STATUS_CUMPLIMIENTO
FROM SNOWFLAKE.ACCOUNT_USAGE.TABLES t
LEFT JOIN SNOWFLAKE.ACCOUNT_USAGE.TAG_REFERENCES tr
  ON t.TABLE_CATALOG = tr.OBJECT_DATABASE
  AND t.TABLE_SCHEMA = tr.OBJECT_SCHEMA
  AND t.TABLE_NAME = tr.OBJECT_NAME
  AND tr.TAG_NAME = 'LEY8968_DATA_CATEGORY'
  AND tr.DOMAIN = 'TABLE'
WHERE t.DELETED IS NULL
  AND t.TABLE_SCHEMA != 'INFORMATION_SCHEMA'
ORDER BY STATUS_CUMPLIMIENTO DESC, t.TABLE_CATALOG, t.TABLE_SCHEMA;

  ref_entity_domain => 'TABLE'
))
WHERE POLICY_KIND = 'PROJECTION_POLICY'
ORDER BY REF_COLUMN_NAME;

5 Monitorear Solicitudes ARCO Pendientes

USE ROLE LEY8968_OFICIAL_DATOS;

SELECT
  REQUEST_ID,
  REQUEST_TYPE,
  TITULAR_ID,
  REQUESTED_BY,
  REQUESTED_AT,
  STATUS,
  DATEDIFF('day', REQUESTED_AT, CURRENT_TIMESTAMP()) AS DIAS_ABIERTO,
  CASE
    WHEN DATEDIFF('day', REQUESTED_AT, CURRENT_TIMESTAMP()) > 5
      THEN 'ATRASADO'
    WHEN DATEDIFF('day', REQUESTED_AT, CURRENT_TIMESTAMP()) > 3
      THEN 'ATENCION'
    ELSE 'DENTRO DEL PLAZO'
  END AS SLA_STATUS
FROM LEY8968_GOVERNANCE.AUDIT.ARCO_LOG
WHERE STATUS = 'PENDIENTE'
ORDER BY REQUESTED_AT ASC;

6 Alerta para Acceso Masivo a Datos Personales

USE ROLE ACCOUNTADMIN;
CREATE OR REPLACE NOTIFICATION INTEGRATION LEY8968_NOTIFICATIONS
  TYPE = EMAIL
  ENABLED = TRUE
  ALLOWED_RECIPIENTS = ($LEY8968_DPO_EMAIL);

USE ROLE LEY8968_OFICIAL_DATOS;

CREATE OR REPLACE ALERT LEY8968_GOVERNANCE.AUDIT.ALERT_MASS_DATA_ACCESS
  WAREHOUSE = LEY8968_TRAINING_WH
  SCHEDULE = 'USING CRON 0 */6 * * * America/Costa_Rica'
  IF (EXISTS (
    SELECT 1
    FROM SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY
    WHERE EXECUTION_STATUS = 'SUCCESS'
      AND ROWS_PRODUCED > 10000
      AND QUERY_START_TIME >= DATEADD('hour', -6, CURRENT_TIMESTAMP())
      AND (QUERY_TEXT ILIKE '%clientes%' OR QUERY_TEXT ILIKE '%datos_personales%')
  ))
  THEN
    CALL SYSTEM$SEND_EMAIL(
      'LEY8968_NOTIFICATIONS',
      $LEY8968_DPO_EMAIL,
      'ALERTA LEY 8968: Acceso masivo a datos personales detectado',
      'Una consulta retorno mas de 10,000 registros de tablas con datos personales en las ultimas 6 horas. Verifique el ACCESS_HISTORY para detalles.'
    );

ALTER ALERT LEY8968_GOVERNANCE.AUDIT.ALERT_MASS_DATA_ACCESS RESUME;
